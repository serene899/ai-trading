# 部署方案（v1.2.0 起适用）

目标：所有者在 iPhone 上能打开一个 HTTPS 地址、登录后使用模拟交易系统，
账户数据（SQLite）持久保存、重启不丢。价格信息为 2026-11-19 查询结果，平台政策会变，上线前再核一眼。

## 已备好的部署条件（代码侧）

- 登录验证：密码 + httpOnly 会话 Cookie，登录失败 5 次锁定 5 分钟。
- Fail-closed：环境变量 `REQUIRE_AUTH=1` 时，密码/密钥没配好服务直接拒绝启动，不会裸奔。
- 单服务形态：后端可直接托管前端构建产物（`frontend/dist` 存在即生效），
  一个进程、一个端口、一个域名，前后端同源——Cookie 与 CORS 都最简单。
- `Dockerfile` 已备：多阶段构建（Node 构建前端 → Python 运行），数据目录 `/data`。
- 数据持久化点只有一个：`DB_PATH` 指向的文件（容器里默认 `/data/data.db`），
  把 `/data` 挂到持久卷即可；备份 = 定期拷贝这个文件。

## 必填环境变量（任何路线都一样）

| 变量 | 值 |
|---|---|
| `REQUIRE_AUTH` | `1` |
| `AUTH_PASSWORD` | 自己定的登录密码（≥8 位）。图省事用这个；更稳妥的是用 `backend/hash_password.py` 生成 `AUTH_PASSWORD_HASH` 代替它 |
| `SESSION_SECRET` | 一长串随机字符串（可用密码生成器随便生成 32 位以上） |
| `COOKIE_SECURE` | `1`（HTTPS 下才发 Cookie） |
| `DB_PATH` | 持久卷上的路径，如 `/data/data.db` |

## 路线 A（推荐）：Render 付费版 — 省心

- 成本：Web Service Starter **$7/月**（0.5 CPU / 512 MB）+ 持久磁盘 **$0.25/GB/月**
  （本系统 1 GB 足够），合计约 **$7.25/月（约 ¥52）**。
- 为什么不用它的免费版：免费 Web 服务 15 分钟无访问就休眠，且文件系统是临时的、
  不能挂持久磁盘——账户数据会丢，对本项目是硬伤。
- 好处：平台自带 HTTPS 和域名（`xxx.onrender.com`）、连接 GitHub 后推代码自动部署、
  不用碰服务器运维。全程可在手机浏览器里完成注册与配置。
- 步骤：注册 Render → New → Web Service → 连接 GitHub 的 `ai-trading` 仓库 →
  运行时选 Docker → 实例选 Starter → Add Disk：挂载路径 `/data`、容量 1 GB →
  在 Environment 里填上表 5 个变量 → Create。部署完成后打开它的域名即可登录使用。

## 路线 B（免费）：Oracle Cloud Always Free — 要折腾

- 成本：**¥0**。Always Free 的 ARM 机器（2026 年现行额度：2 OCPU + 12 GB 内存、
  200 GB 存储）永久免费，跑本系统绰绰有余。
- 代价：① 注册必须用 Visa/Mastercard 信用卡做验证（只冻结小额、不扣费，虚拟卡/预付卡不行）；
  ② 免费 ARM 容量紧俏，部分区域（如东京、首尔）经常缺货，且注册时选的区域以后不能改；
  ③ 有闲置回收规则（连续 7 天 CPU/网络/内存都很低可能被回收，需要保活手段）；
  ④ HTTPS 要自己装 Caddy + 申请域名（可用 DuckDNS 免费子域名）。
- 适合：愿意花一个晚上折腾、换长期零成本的人。Docker 镜像与路线 A 通用，以后互迁成本低。

## 明确不行的路（已核实，免得再试）

- **GitHub Pages**：只能放静态网页，本系统需要常驻后端进程，放不了。
- **Atlas 的这台工作机**：会频繁更新重启，不能承诺服务常在，账户数据库放这儿不安全。
- **Tailscale 私有网**：Atlas 侧的 Tailscale 只能"出去访问"、不能对外提供服务；
  且家里没有一台常开的机器当宿主，这条路缺宿主。

## 上线检查清单（任一路线，部署完逐项核）

1. 打开站点根地址是登录页，不是总览页；
2. 不登录直接访问 `/api/v1/account` 返回 401；
3. 登录后能下单（模拟）、刷新页面不掉登录、重启服务后余额不变；
4. `/health` 返回 `auth_enabled: true`；
5. 备份一份 `data.db` 到本地（部署平台的文件下载或 shell 拷贝），确认能拿到手。

## 备份纪律

- `data.db` 是唯一账本：每周至少手动备份一次；大改版部署前先备份。
- 恢复：停服务 → 用备份覆盖 `DB_PATH` 文件 → 启动。
